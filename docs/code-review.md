# 코드 선별 및 모의 데이터 검증

검토일: 2026년 10월 9일, 한국시간.

이 문서는 첫 번째 오프라인 구현 단계의 선별 기록이다. 이후 추가한 로그인·잔액 조회 어댑터의 상태는 [실서비스 진단 기록](live-diagnostics.md)에 정리했다.

| 원본 구성 | 확인한 문제 또는 결합 | 새 저장소 처리 |
| --- | --- | --- |
| 잔액 알림 | 문구 생성과 HTTP 전송이 같은 함수에 있고 요일이 고정됨 | 출처·관측 시각을 포함한 순수 문구 생성 함수로 새로 구현 |

## 데이터 계약

입력 JSON은 `observed_at`, `status`, 선택적 `balance`, `source`만 허용한다. 시각에는 시간대가 필요하며, 기본 출처는 `fixture`다. 추가 필드는 오류로 처리한다.

- `ok`: 0 이상의 정수 금액 또는 `12,000원` 같은 문자열이 필요하다.
- `unavailable`: 확인할 수 없는 상태이며 잔액은 생략하거나 null로 둔다.
- `error`: 조회 실패 상태이며 잔액은 생략하거나 null로 둔다.

실패 상태에 금액을 함께 넣거나, 성공 상태에서 금액을 생략하면 입력 오류다. 출처는 영문·숫자·밑줄·하이픈 1~40자로 제한한다. 원본 응답·오류 본문·자격 증명은 저장하지 않는다.

## 검증 범위

`python3 -m unittest discover -s tests -v`로 다음을 검증한다.

- 정상 금액과 실제 0원, 잘못된 금액·HTML·음수·불리언 구분
- 성공·미확인·실패 상태의 금액 일관성 및 시간대 검증
- 알림 출처·시각·금액 표시와 실패 상태의 0원 오표시 방지
- SQLite 저장 후 정상·0원·실패 결과 복원
- 기록 읽기 전용 조회와 존재하지 않는 DB 생성 방지
- 정상·미확인·실패 및 잘못된 입력의 CLI 종료 코드
- 잘못된 JSON에서 DB를 만들지 않고 원문을 출력하지 않는 동작
- 소켓 생성을 차단한 상태에서 모의 데이터 미리보기 실행

기존 서비스 로그인 성공, 잔액 페이지 선택자, Discord 전달, 실제 DB나 대시보드 동작은 검증하지 않았다. 다음 단계에서는 실제 서비스의 인증·응답 구조를 별도로 확인하고, 읽기 전용 조회 어댑터와 전송 어댑터를 추가할 수 있다.
