# 로그인·잔액 조회 진단

확인일: 2026년 10월 9일, 한국시간.

## 기존 코드에서 확인한 문제

- `lotoManager`: 특정 비밀번호 오류 문구가 없으면 로그인 성공으로 처리한다. 이후 HTTP 상태·인증 여부·요소 존재를 검사하지 않고 `.total_new strong`의 `.get_text()`를 호출한다. 요소가 없을 때 `NoneType` 예외가 발생하지만, 왜 요소가 없는지는 그 예외만으로 알 수 없다.
- `vibe-lotto`: RSA 키 조회와 로그인 요청을 사용하지만 로그인 응답에서 인증 성공을 검증하지 않는다. 잔액 JSON에 `totalAmt`가 없으면 `0원`을 반환해 미확인 상태를 실제 0원과 혼동한다.
- [현재 공식 로그인 화면](https://www.dhlottery.co.kr/login)은 별도 `/login` 경로에서 제공된다. 기존 HTML 선택자가 정상인지, 과거 오류가 로그인 실패인지 구조 변경인지까지 이 공개 페이지로 확정할 수는 없다.

## 새 어댑터

`monitor/live.py`는 기존 `vibe-lotto`의 경로와 응답 필드를 참고해 새로 구현했다. 공개 문서화된 공식 API 계약이 아니므로 사이트 변경에 따라 수정이 필요할 수 있다.

1. `/login`과 비인증 잔액 응답을 확인한다. 비인증 상태에서도 금액이 나오면 인증 증거가 부족하므로 중단한다.
2. `/login/selectRsaModulus.do`에서 키를 읽고 자격 증명을 암호화한다.
3. `/login/securityLoginCheck.do`에 로그인 요청을 한 번 보낸다.
4. `/mypage/selectUserMndp.do`에서 검증 가능한 정수 금액이 나온 경우에만 성공을 반환한다.

로그인 POST만 성공하거나 쿠키만 생긴 것은 성공으로 보지 않는다. 응답이 HTML이거나 금액 필드가 없으면 미확인으로, 잘못된 JSON·금액은 오류로 처리한다. HTTP 오류·접근 차단·요청 제한은 중단한다. 요청에는 연결·응답 제한 시간이 있으며 다른 호스트로 리다이렉트하지 않는다. 로그인 POST 데이터는 리다이렉트 대상으로 재전송하지 않는다.

`--diagnostic`은 상태, 단계, 고정 코드만 출력한다. 실제 금액·아이디·비밀번호·쿠키·원본 응답은 진단 로그와 공개 문서에 포함하지 않는다. 진단 실행은 Discord·개인 서버·구매 경로를 호출하지 않는다.

## 검증 상태

모의 HTTP 응답으로 정상 금액·0원·미인증 HTML·필드 누락·접근 차단·요청 제한·리다이렉트·전송 예외·JSON 오류를 검증했다. 선택적 의존성을 설치한 환경에서는 RSA 암호화 왕복도 검증한다.

기존 비공개 `vibe-lotto`의 Secrets를 사용하는 수동 `Monitor Balance Diagnostic` 워크플로에서 실제 계정으로 로그인·잔액 조회를 확인했다. 검증한 공개 코드 커밋은 `68b6cb8`이며, [검증 실행](https://github.com/k-ubella/vibe-lotto/actions/runs/37902867023)은 비공개 저장소 접근 권한이 필요하다. 진단 결과는 다음과 같다.

```json
{"status": "ok", "stage": "balance", "code": "balance_verified"}
```

실제 금액은 공개하지 않았다. 인증 전 잔액 API의 401·403은 정상적인 인증 요구일 수 있어 로그인 전 검사에서는 허용하고, 인증 후 같은 응답은 실패로 처리한다. 첫 진단에서는 로그인 페이지 연결 단계의 전송 오류가 있었고, 다음 진단에서는 인증 전 접근 거부를 너무 일찍 실패 처리한 부분을 발견해 수정했다. 로그인 POST가 수행되기 전에 중단됐던 두 진단을 반복 로그인 성공으로 계산하지 않는다.

선택적 의존성을 설치한 환경에서 총 31개 테스트가 통과했고, 공개 저장소의 Python 3.10·3.12 CI도 성공했다. 오프라인 기본 테스트에서는 선택적 의존성이 없는 경우 RSA·전송 예외 테스트를 건너뛴다.

이번 결과는 점검 당시 한 번의 실제 조회 성공이다. 장기간 운영 안정성, Discord 전달, 구매·당첨 내역, 대시보드 동작을 검증했다는 뜻은 아니다. 수동 진단은 검토한 공개 코드의 전체 커밋 SHA를 고정해 실행하며, 자격 증명은 비공개 저장소에서만 사용한다. 기존 예약 워크플로는 다시 활성화하지 않았다.

후속 검증에서는 실제 잔액 조회부터 Discord 전송·재조회까지 통합 실행이 성공했다. 실제 금액은 로그에 출력하지 않았다. 결과와 실행 링크는 [전송 검증 기록](discord-delivery.md)에 정리했다. 예약·장기간 운영은 아직 검증하지 않았다.
